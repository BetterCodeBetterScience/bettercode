# Design: `tex2qmd` — Rerunnable LaTeX → Quarto HTML Pipeline

**Date:** 2026-07-03
**Author:** Russell Poldrack (design brainstormed with Claude)
**Status:** Approved for planning

## Goal

Produce an HTML version of *Better Code, Better Science* that can be served
via GitHub Pages, generated from the LaTeX source by a **rerunnable workflow**.
The LaTeX (`latex/book.tex` and its chapters) remains the single source of
truth; the HTML/Quarto artifacts can always be regenerated to reflect the
current LaTeX.

Direct LaTeX→HTML conversion was rejected because the book's custom Cambridge
document class (`EngD.cls`) plus `designchanges.sty` do not translate cleanly to
the web. Instead we extract **semantic content** (prose, code, figures, math,
citations, cross-references) out of the `.tex` and let Quarto's own book theme
supply the web design.

## Core Principles

1. **Single source of truth.** `book.tex` and chapter `.tex` files are authored;
   the pipeline only *mechanically extracts* from them. Generated `.qmd` files are
   **never hand-edited**.
2. **Regenerable, not committed.** The generated Quarto project and its rendered
   output are gitignored. Only the pipeline code, tests, config templates, and the
   CI workflow are committed.
3. **Drop the print design.** `designchanges.sty` is intentionally *not* carried
   over. Quarto's book theme provides styling, navigation, and full-text search.
4. **Respect the "no editing narrative text" rule.** Prose is transformed
   programmatically, never authored or hand-edited. If a construct cannot be
   converted faithfully, surface it — do not rewrite the prose.

## Scope Decisions (confirmed)

- **Target:** Full book (preface + 12 chapters), but the pipeline is developed and
  validated on `book-testing.tex` first (the cleanest chapter), then generalized.
- **Code listings:** Static display only. Captured outputs are (re)generated by the
  existing `scripts/build_listings.py` manifest pipeline and inlined; Quarto does
  **not** execute code.
- **Deployment:** GitHub Actions → GitHub Pages, regenerating from source on push.
- **Conversion engine:** Pandoc, wrapped by a custom Python pre/post-processing pass.
- **Index:** The back-of-book index (419 `\index` entries, `\printindex`) is dropped;
  Quarto's built-in full-text search replaces it.
- **Figures:** The 46 figure PDFs are converted to SVG (vector), with PNG fallback.
- **Output location:** A **top-level `web/` directory** (sibling of `latex/`), kept
  separate from the LaTeX build. Gitignored.

## Source Inventory (from analysis)

- `latex/book.tex`: `\include`s preface + 12 chapters (~12k lines total). Custom
  `EngD.cls` / `cambridge7A.cls` + `designchanges.sty`.
- **Code listings, two kinds:**
  - `\lstinputlisting[style=X, firstline=a, lastline=b]{path}` pulling from
    `../src`, `../tests`, and `generated/` (62 in the testing chapter alone).
  - 408 inline `\begin{lstlisting}[style=X]…\end{lstlisting}` blocks tagged with
    styles: `Python`/`Pythonshort`, `R`, `shell`/`shellshort`, `repl`/`replshort`,
    `yaml`, `toml`, `json`, `dockerfile`, `makefile`, `transcript`/`transcriptshort`,
    `Rust`.
- **Generated outputs:** `latex/generated/<chapter>/*.txt` produced by
  `scripts/build_listings.py` from `latex/manifests/<chapter>.yaml`. Gated by
  `make verify-listings`.
- **Figures:** 46 PDFs under `latex/figures/NN/`.
- **Citations:** natbib (`\citep` ×102, `\citet` ×2, `\cite` ×12) + `references.bib`
  + `cambridgeauthordate.bst`.
- **Cross-references:** 55 `\label`, 59 `\ref`.
- **Other environments:** `itemize`, `enumerate`, `figure`, `table`, `tabular`,
  `quote`, `framed`, `equation`.
- **Tooling present:** `pandoc`, `quarto`, `latexml` all installed.

## Component Architecture

A focused Python package `scripts/tex2qmd/` (run via `uv run`), split into
single-purpose modules:

| Module | Responsibility |
|---|---|
| `preprocess.py` | Resolve LaTeX-specific constructs before pandoc: inline `\lstinputlisting` (with `firstline`/`lastline` slicing), rewrite `\includegraphics` PDF paths, strip `\index{}`, tag listing styles for the language map. |
| `listings.py` | Map `lstlisting` styles → fenced-code languages (Python/Pythonshort/repl/replshort → `python`; shell/shellshort → `bash`; transcript/transcriptshort → `text`; `R` → `r`; yaml/toml/json/dockerfile/makefile/Rust → same-named fence). |
| `figures.py` | Convert `figures/NN/*.pdf` → SVG (PNG fallback), carry LaTeX `width=` as a Quarto image attribute, rewrite paths into `web/figures/`. |
| `pandoc_bridge.py` | Feed cleaned per-chapter LaTeX to `pandoc --from latex --to markdown`; converts prose, math, `\citep/\citet` → `[@key]`, `\ref/\label` cross-refs, tables, quotes, equations. |
| `postprocess.py` | Normalize pandoc output into Quarto idioms: cross-reference anchors, `framed` → callout div, figure fences/captions. |
| `project.py` | Emit `_quarto.yml` (chapter order parsed from `book.tex` `\include` sequence, book theme, search enabled, `bibliography:` + `csl:`); copy `references.bib`; provide a Cambridge author-date `.csl`. |
| `convert.py` | CLI orchestrator: `uv run python -m tex2qmd <chapter|all>`. |

## Data Flow

```
latex/book.tex  (source of truth)
   │
   ├─ scripts/build_listings.py build/verify   → regenerates latex/generated/*.txt
   │
   ▼
tex2qmd: per chapter → preprocess → pandoc → postprocess
   │                   + figures PDF→SVG
   │                   + project.py builds _quarto.yml from \include order
   ▼
web/  (index.qmd, book-testing.qmd, …, figures/*.svg, references.bib, cambridge.csl)   [gitignored]
   │
   ▼
quarto render  →  web/_book/  →  GitHub Pages
```

New `make` targets in `latex/Makefile` (or a top-level Makefile):
- `make quarto` — verify/build listings → convert all chapters → `quarto render`.
- `make quarto-serve` — live preview during development.

## Conversion Detail Notes

- **`\lstinputlisting`:** read the referenced file (paths resolved relative to
  `latex/`), apply `firstline`/`lastline` slicing if present, emit a fenced code
  block with the mapped language. Covers `../src`, `../tests`, and `generated/`.
- **Inline `lstlisting`:** convert body verbatim into a fenced block with the
  mapped language; `*short` variants map to the same language (line-number and
  caption differences are print-only and dropped).
- **Figures:** `\includegraphics[width=0.6\linewidth]{figures/07/foo.pdf}` →
  convert `foo.pdf`→`foo.svg`, rewrite to `figures/07/foo.svg`, and express width as
  a Quarto attribute (e.g. `{width=60%}`). Enclosing `figure`/caption/`\label`
  preserved so Quarto can build a numbered, linkable figure.
- **Citations:** pandoc converts `\citep{key}`/`\citet{key}` to markdown `[@key]`;
  Quarto resolves them at render via `bibliography: references.bib` + a Cambridge
  author-date CSL.
- **Cross-references:** `\label`/`\ref` mapped by pandoc; postprocess normalizes to
  Quarto anchors where needed. Imperfect matches are logged, not silently dropped.
- **Index:** all `\index{…}` stripped in preprocess; `\printindex` omitted.

## Testing (TDD — non-negotiable)

Tests are written and committed **before** implementation (RED → GREEN → Refactor).
Unit tests use small `.tex`/source fixtures for each pure transform:

- style → language mapping (all styles, including `*short` variants)
- `\lstinputlisting` line-range slicing (with and without `firstline`/`lastline`)
- figure-path rewrite + width-attribute translation
- `\index{…}` stripping (including nested `!` subentries)
- citation conversion (`\citep`, `\citet`, `\cite`)
- `_quarto.yml` chapter-order extraction from `book.tex`

Tests are functions (not classes), with pytest fixtures for shared fixture
directories; test functions get docstrings but no type hints. End-to-end
conversion of `book-testing.tex` is verified visually against the PDF.

## Milestones

1. Scaffold `scripts/tex2qmd/` package + write failing tests for the pure transforms (RED). Commit tests.
2. Implement `preprocess`/`listings`/`figures`/`project` to green.
3. End-to-end convert **book-testing.tex** → render → visually verify vs. the PDF.
4. Generalize across the remaining 11 chapters + preface; fix per-chapter edge cases.
5. Add `.github/workflows/deploy-quarto.yml`; publish to GitHub Pages.

## Out of Scope

- Reproducing the print design (`designchanges.sty`, custom class styling).
- Live code execution in Quarto (outputs come from the existing manifest pipeline).
- A back-of-book HTML index page (search replaces it).
- Editing any narrative prose.
